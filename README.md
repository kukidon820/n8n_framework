# n8n-transcriper

Конвертер экспортированных workflow из n8n в самостоятельные Python-проекты. Он читает JSON только при генерации, анализирует связи и expressions, затем создаёт обычные функции и явный порядок вызовов в <code>main.py</code>. Исходный workflow и n8n для запуска результата не нужны.

Для обычных шагов создаётся отдельный Python-модуль. Ветвления, циклы и объединения преобразуются в видимый Python-код. Триггеры не запускаются и не входят в исполняемый граф; их имя, тип и параметры записываются в README сгенерированного проекта. Точка запуска остаётся ручной — <code>main.py</code>.

Любой поддерживаемый тип узла можно использовать в workflow сколько угодно раз. Это относится и к последовательным или вложенным узлам <code>Loop Over Items</code>; ограничения относятся к соединениям каждого отдельного узла и описаны в [документе ограничений](docs/limitations.md).

## Установка

Нужны Python 3.12 или новее и <code>uv</code>. В корне репозитория выполните:

    uv sync

## Команды

Показать справку:

    uv run n8n-transcriper --help

Проверить структуру workflow и вывести его узлы:

    uv run n8n-transcriper inspect workflow.json

Проверить workflow, поддержку узлов и выражений, а также сгенерированный Python-код без записи проекта:

    uv run n8n-transcriper validate workflow.json

Создать проект:

    uv run n8n-transcriper convert workflow.json --out generated

В качестве короткой команды преобразования также доступно:

    uv run python convert.py workflow.json --out generated

Необязательный режим LangGraph:

    uv run n8n-transcriper convert workflow.json --out generated --langgraph
    uv run n8n-transcriper validate workflow.json --langgraph

Без флага конвертер использует обычные вызовы сгенерированных Python-функций. Флаг добавляет LangGraph в generated-проект. Только в этом режиме HTTP Request проверяются на AI-вызов по адресу endpoint и структуре JSON-тела; обычная конвертация от этого не меняется. Поддерживаемые адреса и критерии распознавания описаны в [справочнике узлов](docs/supported-nodes.md#http-запросы-к-модели-в-режиме-langgraph).

Каталог назначения должен отсутствовать или быть пустым. Конвертер создаст в нём только файлы и зависимости, нужные этому workflow: <code>main.py</code>, <code>config.py</code>, <code>pyproject.toml</code>, <code>uv.lock</code>, <code>requirements.txt</code>, README, отчёт и модули узлов.

## Запуск созданного проекта

Перейдите в каталог результата, установите зафиксированные зависимости и запустите workflow:

    cd generated
    uv sync --locked
    uv run python main.py

Для запуска через скрипт используйте <code>run.bat</code> на Windows или <code>sh run.sh</code> на Linux/macOS. Если workflow ожидает входные данные, передайте их в <code>run()</code> вручную:

    from main import run

    result = run([{"json": {"name": "Пример"}}])

Если аргумент не передан, точка входа получает один пустой item. Элементы имеют n8n-подобную форму: <code>{"json": {...}, "binary": {...}}</code>. Бинарные файлы представлены байтами.

В async-приложении используйте <code>await run_async(input_data)</code> из <code>main.py</code>. Каждый сгенерированный узел — async-функция; HTTP, SMTP и PostgreSQL используют асинхронные клиенты.

Сгенерированный <code>main.py</code> выводит логи запуска workflow и шагов; при ошибке указывает узел и причину, затем пробрасывает исключение.

## Частичная конвертация

Команда <code>convert</code> старается создать проект даже тогда, когда часть workflow нельзя перенести автоматически.

Если тип узла поддерживается, но в нём есть неизвестный параметр, режим или неподдерживаемое expression, генератор оставляет узел в проекте как TODO-функцию. При её вызове возникает <code>NotImplementedError</code>, пока пользователь не реализует отмеченное поведение вручную. Причина показывается в generated <code>main.py</code>, README и <code>conversion_report.md</code>.

Если не поддерживается сам тип узла или соединение, либо отсутствует обязательная ссылка на credentials, соответствующий узел может быть исключён из сгенерированной части. Связи через исключённый узел упрощаются, поэтому входные данные соседних функций могут отличаться от исходного workflow. Перед запуском просмотрите отчёт и комментарии, восстановите нужную логику вручную.

Неподдерживаемые общие настройки исполнения также могут привести к пропуску узла. Смотрите точный статус каждого узла в <code>conversion_report.md</code>: TODO-функция прервёт выполнение при вызове, а пропущенный узел в generated-графе отсутствует.

<code>validate</code> проверяет workflow целиком и завершается с кодом ошибки при блокирующих проблемах, например при отсутствующих обязательных credentials или неподдерживаемом соединении. Это не запрещает <code>convert</code> записать доступную часть проекта. Ошибки чтения JSON и workflow без узлов требуют исправления исходного файла.

Триггеры не запускаются, и проверка workflow не требует ставить их первыми. Их имя, тип и параметры описываются в README сгенерированного проекта; запуск начинается вручную из <code>main.py</code>.

## Credentials и переменные окружения

Сгенерированный <code>config.py</code> показывает, какие секреты и настройки необходимы проекту. Секреты из n8n в Python-код не переносятся.

Для узла, которому нужны credentials, в JSON должна присутствовать ссылка на credential нужного типа. Если обязательной ссылки нет, <code>validate</code> сообщит об этом и завершится с ошибкой; <code>convert</code> продолжит генерацию, но пропустит затронутый узел. Когда ссылка есть, укажите реальные значения в перечисленных переменных окружения или в локальном <code>config.py</code>. Проверьте список пропусков в <code>conversion_report.md</code> перед запуском.

Примеры для PowerShell:

    $env:OPENROUTER_CHAT_MODEL_API_KEY = "ваш-ключ"
    $env:SMTP_USERNAME = "your-account@gmail.com"
    $env:SMTP_APP_PASSWORD = "пароль-приложения"

Для Linux/macOS:

    export OPENROUTER_CHAT_MODEL_API_KEY="ваш-ключ"
    export SMTP_USERNAME="your-account@gmail.com"
    export SMTP_APP_PASSWORD="пароль-приложения"

Это имена для соответствующих узлов примера. Для конкретного workflow сверяйтесь с generated <code>config.py</code>; файл <code>.env</code> автоматически не загружается. Не записывайте реальные ключи и пароли в репозиторий.

## Поддерживаемые узлы

| Узел | Реализация |
|---|---|
| Python Code | Перенос исходного Python-кода в функцию; запуск для всех items или каждого item |
| HTTP Request | Отдельный HTTP-вызов с настройками запроса, ответа, авторизации, retry, batching и ограниченной пагинацией |
| Send Email | Создание MIME-письма и отправка через SMTP |
| Convert to File | CSV, HTML, iCal, JSON, ODS, RTF, текст, XLS, XLSX и binary |
| Compression | ZIP-архивирование и распаковка с bytes |
| Extract From File | Чтение текста из binary или преобразование binary в base64 |
| Edit Fields (Set) | Assignments, выбор исходных полей, binary и обработка ошибок приведения типов |
| No Operation | Передача входных items без изменений |
| IF и Switch | Маршрутизация items по условиям |
| Merge | Только Append и Combine |
| Loop Over Items | Класс <code>Loop</code> с размером пакета, reset, Execute Once и Retry On Fail |
| Wait | Асинхронная пауза по интервалу или до заданной даты; для режимов webhook/form создаётся TODO-заготовка с диагностикой |
| AI Agent | В обычном режиме — HTTP-вызов подключённой модели; в режиме LangGraph — адаптер поддерживаемого провайдера. Tools и streaming не поддерживаются |
| Data Table | Операции со строками PostgreSQL через asyncpg |
| PostgreSQL | Простые SQL-запросы через psycopg |

Список ситуаций, в которых проверка завершится ошибкой, узел будет пропущен или запуск прервётся, приведён в [ограничениях](docs/limitations.md).

Справочник [описывает поддерживаемые параметры и ограничения каждого узла](docs/supported-nodes.md). В [обзоре архитектуры](docs/architecture.md) объяснено устройство generated-проекта. Команды установки и разработки приведены в [руководстве разработчика](docs/development.md).

## Проверки и разработка

Запуск unit-тестов:

    uv run pytest

Интеграционная проверка PostgreSQL пропускается, если не задан порт тестового сервера. Условия запуска описаны в [руководстве разработчика](docs/development.md).
