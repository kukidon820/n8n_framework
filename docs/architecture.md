# Архитектура

## Принцип работы

Конвертер использует JSON и граф workflow только во время генерации. Он проверяет связи, порядок узлов и выражения, затем пишет независимый Python-проект. В сгенерированном проекте нет интерпретатора n8n и нет обязательной зависимости от исходного JSON.

Общий путь данных:

1. `reader.py` читает UTF-8 JSON и проверяет обязательные поля.
2. `graph.py` преобразует `connections` в связи и вычисляет топологический порядок по каналу `main`.
3. `expressions.py` переводит поддерживаемые expressions в Python и собирает зависимости от именованных узлов.
4. `converters/` генерирует код для конкретных типов узлов.
5. `generator.py` соединяет модули в `main.py`, создаёт `config.py`, `requirements.txt`, README и отчёт.

AI-соединение `ai_languageModel` связывает подключённую chat-модель с Agent и не становится отдельным последовательным вызовом. Для агента без инструментов генерируется HTTP-вызов OpenAI-compatible Chat Completions API; адрес и credentials находятся в `config.py`. Неизвестные дополнительные каналы и неподдерживаемые графы отклоняются с `WorkflowError`.

HTTP Request к Gmail `users/me/messages/send` генерирует SMTP-отправитель в отдельном `email_senders/` модуле. Он декодирует подготовленное MIME-сообщение и отправляет его через STARTTLS с `SMTP_USERNAME` и паролем приложения. Другие Gmail API запросы остаются HTTP-вызовами с OAuth2.

## Структура исходного пакета

```text
src/n8n_transcriper/
├── cli.py                 # Typer: convert и inspect
├── reader.py              # чтение и проверка JSON
├── graph.py               # связи и порядок исполнения
├── expressions.py         # компиляция expressions
├── generator.py           # план генерации и main.py
└── converters/
    ├── ai.py
    ├── code.py
    ├── conditions.py
    ├── edit_fields.py
    ├── files.py
    ├── http.py
    ├── merge.py
    └── postgres.py
```

Каждый converter отвечает за параметры своего типа узла. Параметры, которые нельзя применить без потери поведения, вызывают диагностическую ошибку; генератор не вставляет фиктивный успешный результат.

## Сгенерированный проект

`main.py` — ручная точка входа `run(input_data=None)`. Обычные линейные шаги представлены последовательными вызовами. IF и Switch становятся ветвлением, а Merge получает отдельные списки входов. Каждый преобразованный узел импортируется из собственного файла, названного по имени узла; при совпадениях имя стабилизируется суффиксом ID.

Результаты предыдущих узлов хранятся под именами узлов для заранее скомпилированных ссылок. Для `.item` генератор добавляет внутренние индексы связей между исходными и выходными items. Эти служебные ключи удаляются из результата `run()`.

Элементы передаются как словари с полем `json`; бинарные файлы представлены байтами в `binary`. Сгенерированные функции меняют только нужные поля, сохраняя прочие JSON-данные и binary там, где этого требует операция.

## Credentials и зависимости

`config.py` читает секреты из переменных окружения. `requirements.txt` содержит только библиотеки, необходимые узлам конкретного workflow: например, `httpx` для HTTP и AI Chat Completions, `psycopg[binary]` для PostgreSQL. Секреты workflow не копируются в generated source.
