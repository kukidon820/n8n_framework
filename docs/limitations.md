# Ограничения и поведение ошибок

Этот документ описывает, что конвертер перенесёт автоматически, что пометит для ручной доработки и в каких случаях generated-проект не запустится. Параметры каждого узла перечислены в [справочнике поддерживаемых узлов](supported-nodes.md).

## Сколько узлов можно использовать

Общего лимита на количество узлов одного типа нет. В одном workflow могут повторяться HTTP Request, Code, Edit Fields, AI Agent и любые другие поддерживаемые типы. Это относится и к Loop Over Items: разрешены последовательные, независимые и вложенные циклы. Имена и ID узлов в JSON должны быть уникальными.

Ограничения относятся к структуре конкретного узла и общему графу:

- В исполняемой части workflow должна быть одна начальная точка.
- Узлы Loop должны использовать штатные выходы loop/done и штатную обратную связь; остальные циклы графа не поддерживаются.
- Каждый вход Merge должен иметь ровно одно соединение.
- Каждый AI Agent должен иметь ровно одно соединение <code>ai_languageModel</code>. Один и тот же узел модели можно использовать в нескольких Agent.
- Узлы-триггеры не запускаются и удаляются из исполняемого графа. Триггер не нужно ставить первым; он будет описан в README generated-проекта.

## Что делают convert и validate

| Ситуация | <code>validate</code> | <code>convert</code> |
|---|---|---|
| Нечитаемый UTF-8, ошибочный JSON, неверная структура <code>nodes</code>/<code>connections</code>, повторяются имена или ID, ошибочны ссылки соединений | Выводит диагностику и завершает работу с кодом 1. Ошибку чтения файла или JSON продолжить проверять нельзя. | Не создаёт пригодный проект; сначала исправьте исходный JSON. |
| Несколько независимых ошибок структуры, параметров или expressions | Собирает доступные диагностики, продолжает проверки, когда это безопасно, и завершается с кодом 1. | Пытается сохранить доступную часть workflow. |
| Версия узла вне проверенного диапазона | Выводит предупреждение. Сама версия не является блокирующей ошибкой. | Использует fallback для версии там, где он определён. |
| Неизвестная или неподдерживаемая настройка поддерживаемого узла | Показывает путь параметра и предупреждение либо ошибку конвертации. | Если доступна ручная заготовка, оставляет функцию с TODO и <code>NotImplementedError</code>. При выполнении этой функции запуск остановится. |
| Неподдерживаемый тип узла, обязательная ссылка на credential отсутствует, неподдерживаемый дополнительный канал | Сообщает об узле и причине, завершает с ошибкой. | Может пропустить узел и упростить связи через него. Результат соседнего узла поэтому может отличаться от n8n. |
| Неподдерживаемая форма графа | Сообщает об ошибках связей, портов или порядка. | Пытается исключить проблемную часть. Если связный граф собрать нельзя, результат может содержать только каркас и отчёт. |
| Ошибка запроса, SQL, файловой операции или отсутствующая runtime-настройка | Не проверяет доступность внешнего сервиса или фактическое выполнение. | Ошибка возникнет при запуске; generated-логи укажут узел, затем исключение прервёт выполнение. |

После <code>convert</code> откройте generated <code>README.md</code> и <code>conversion_report.md</code>. Ориентируйтесь на фактическую отметку для узла: «пропущен» означает, что его шаг удалён, а «TODO» — что шаг есть, но требует реализации.

## Структура workflow и соединения

- Узлы должны иметь уникальные непустые <code>id</code>, <code>name</code> и <code>type</code>; <code>parameters</code> должен быть объектом. Connections должны ссылаться на существующие узлы и допустимые выходы.
- После исключения триггеров и подключённых моделей исполняемый граф должен иметь одну начальную точку. Несколько несвязанных workflows автоматически не объединяются.
- Для обычных узлов используется канал <code>main</code>. IF, Switch, Merge и Loop имеют специальные правила портов; произвольные каналы не трактуются как main-соединения.
- Цикл в main-графе разрешён только как обратная связь Loop Over Items. Циклы, созданные другими узлами, вызывают ошибку графа.
- Поддерживаемые типы узлов можно повторять без ограничения количества. Это не отменяет требований к уникальности имени и ID.

### Loop Over Items

Количество Loop не ограничено, но каждый из них должен иметь корректную локальную схему:

1. Один начальный main-вход на индекс входа 0.
2. Подключённый выход loop и непустую область достижимых узлов тела.
3. Ровно одну обратную связь из тела на вход 0 Loop; у обратной связи используются выход 0 источника и вход 0 цикла.
4. Если подключена ветка done, её область не должна пересекаться с телом.
5. Вложенный Loop должен целиком находиться внутри тела внешнего Loop. Частичное пересечение областей двух циклов не поддерживается.

Нарушение этих условий даёт сообщение с именем Loop или узла, где найдено нарушение. Пустое тело, несколько обратных связей, обратная связь не из тела, вход в тело извне или несколько входных потоков в один Loop не преобразуются. Произвольные циклы, не принадлежащие Loop, тоже не преобразуются.

### Merge и AI Agent

- Merge поддерживает только Append и Combine. Append принимает от 2 до 10 входов. Combine по полям и декартово произведение требуют два входа; детали вариантов и join mode приведены в [справочнике узлов](supported-nodes.md#merge).
- Для каждого AI Agent нужна ровно одна chat-модель через <code>ai_languageModel</code>, вход 0. Один узел модели можно использовать для нескольких Agent.
- <code>ai_tool</code>, <code>ai_memory</code> и другие дополнительные AI-соединения не исполняются. Agent с такими соединениями пропускается с объяснением.

## Общие настройки выполнения узлов

- Trigger/Webhook не запускаются. Generated <code>main.py</code> начинает работу вручную.
- <code>disabled=true</code>, <code>continueOnFail=true</code> и значения <code>onError</code>, отличные от <code>stopWorkflow</code>, не переносятся.
- <code>retryOnFail</code> реализован для HTTP Request и Loop Over Items. Для остальных типов включённый retry не переносится и приводит к диагностике/пропуску узла. Retry контроллера Loop не повторяет ошибки узлов внутри тела.
- <code>executeOnce</code> и <code>alwaysOutputData</code> поддерживаются не для всех типов. Значение true не поддерживается для IF, Switch и Merge; у Loop <code>executeOnce</code> оставляет первый входной item.
- Runtime-ошибка по умолчанию останавливает workflow. <code>continueOnFail</code> автоматически не эмулируется.

## Ограничения по узлам

| Узел | Ограничение и результат при его нарушении |
|---|---|
| Python Code | Поддерживается только Python/Python Native. JavaScript Code не исполняется и не переводится. Неизвестные n8n helpers или контекстные переменные требуют ручной адаптации; неподдерживаемый код не должен выдаваться за готовую логику. |
| HTTP Request | Поддерживаются только методы, auth, форматы тела и options из справочника. Proxy с login/password в URL не поддерживается. Pagination ограничена GET без тела и JSON-ответом; нужен положительный предел страниц. Для pagination по next URL авторизация не поддерживается, URL следующей страницы должен быть абсолютным HTTP/HTTPS. Pagination несовместима с <code>fullResponse</code> и <code>neverError</code>. |
| Send Email | Только SMTP. В JSON должна быть ссылка на SMTP credential; пользователь отдельно задаёт username/password. Требуется SSL или STARTTLS. Реальные secrets n8n не экспортируются. |
| Convert to File | Реализованы только операции из справочника: таблицы CSV/HTML/RTF/ODS/XLS/XLSX, JSON, Text, Binary и iCalendar. Неизвестная операция или параметры требуют ручной реализации. Expressions для полей iCalendar не вычисляются; для workflow timezone необходимо задать timezone и включить соответствующую настройку. |
| Compression | Только ZIP Compress и Decompress. <code>outputFormat</code> и <code>outputPrefix</code> не поддерживаются; каталоги при распаковке пропускаются. |
| Extract From File | Только Text и Binary to Property (base64). Извлечение CSV и остальные операции не поддерживаются. |
| Edit Fields / Set | Только Manual Mapping. Списки полей Include/Except должны быть статическими; динамические списки и сложные пути выбора не поддерживаются. При включённом dot notation неоднозначные имена с точками или скобками отклоняются. |
| IF / Switch | Условия должны использовать поддерживаемые типы и операторы из справочника. IF Options вне перечисленных не поддерживаются; Switch поддерживает режим Rules. |
| Merge | Только Append/Combine. Choose Branch, SQL и другие режимы n8n не поддерживаются. Combine по полям требует корректных пар; неоднозначный linked-item reference не подменяется первым item. |
| Wait | Поддерживаются интервал и заданное время. Webhook/Form Resume требуют сервера и сохранения состояния; standalone-проект оставляет TODO-заготовку. |
| AI Agent | Tools, Memory, дополнительные AI-порты и потоковое выполнение не поддерживаются. На каждый Agent нужна одна поддерживаемая chat-модель. В обычном режиме используется HTTP chat-адаптер; в режиме LangGraph — адаптер провайдера. |
| Data Table | Только Row: Insert/Get/Update/Upsert/Delete. Пользовательские значения должны быть скалярными; запись системных колонок запрещена. Внешнюю PostgreSQL-таблицу и соответствие <code>DATA_TABLES</code> нужно создать/настроить вручную. Update/Upsert/Delete требуют хотя бы один фильтр. |
| PostgreSQL | Только Execute Query и проверенное подмножество SELECT/INSERT/UPDATE/DELETE с параметрами <code>$1</code>, <code>$2</code> и далее. Сложный или динамический SQL и конструкции вне поддерживаемого подмножества требуют ручной реализации. |
| Expressions | Поддерживается подмножество n8n expressions. Произвольный JavaScript, методы и сложные вычисления не выполняются через eval; неподдержанное выражение получает диагностику или TODO. Неоднозначная linked-item-ссылка выдаёт ошибку, а не выбирает случайный item. |

Подробные пути параметров, default-значения, режимы и версии приведены в [справочнике узлов](supported-nodes.md).

## AI HTTP-запросы с флагом --langgraph

Распознавание включается только при <code>convert --langgraph</code> или <code>validate --langgraph</code>. Детектор требует POST, JSON body и совместимые признаки endpoint/body. Для стандартного API проверяются host и путь; для собственного адреса нужна сильная сигнатура тела. Одного массива <code>messages</code> недостаточно.

| Провайдер | Примеры endpoint |
|---|---|
| OpenAI | <code>api.openai.com/v1/chat/completions</code> |
| DeepSeek | <code>api.deepseek.com/v1/chat/completions</code>, <code>/chat/completions</code> |
| OpenRouter | <code>openrouter.ai/api/v1/chat/completions</code>, <code>api.openrouter.ai/api/v1/chat/completions</code> |
| Anthropic | <code>api.anthropic.com/v1/messages</code> |
| Google Gemini | <code>generativelanguage.googleapis.com/...:generateContent</code>, <code>:streamGenerateContent</code>, <code>/v1/interactions</code> или <code>/interactions</code> |
| Ollama | <code>/api/chat</code>, <code>/api/generate</code> на localhost или хосте с портом 11434 |

Для неизвестного host распознаётся OpenAI-compatible форма <code>model</code> + role-based <code>messages</code> + параметр генерации; Gemini-compatible <code>contents</code> с текстовыми parts и параметром генерации; либо <code>model</code> + <code>prompt</code> + параметр генерации. Собственный OpenAI-compatible endpoint должен вернуть <code>choices[0].message.content</code>. Для Gemini Interactions с <code>stream=true</code> generated адаптер выдаёт runtime-ошибку; потоковая выдача другими адаптерами также не сохраняет исходную семантику streaming.

Распознанный HTTP-узел превращается из обычного запроса в вызов модели. Не считайте перенесёнными его pagination, batching, timeout/retry, response format или redirects. Параметры из <code>queryParameters</code> n8n не переносятся отдельно. Query-часть URL собственного endpoint сохраняется, кроме параметров, похожих на секреты; для известных API строится базовый URL провайдера. Задавайте ключи в generated <code>config.py</code> или окружении.

## Credentials, версии и среда выполнения

- Workflow содержит ссылки на credentials, но не секреты. Без обязательной ссылки <code>validate</code> завершится с ошибкой, а <code>convert</code> пропустит затронутый узел. Секреты в generated config задаются отдельно.
- Для HTTP generic auth поддерживаются только типы из справочника. OAuth1, Digest и произвольные схемы требуют отдельного адаптера.
- Неизвестный <code>typeVersion</code> сам по себе не блокирует генерацию. Конвертер выдаёт предупреждение и использует fallback/default, где он предусмотрен; новые поля могут быть отмечены как TODO.
- Файл <code>.env</code> автоматически не загружается. Создайте переменные окружения перед запуском или задайте значения в локальном generated <code>config.py</code>. Не коммитьте реальные секреты.
- Generated-зависимости описываются в <code>pyproject.toml</code> и фиксируются в <code>uv.lock</code>. Если <code>uv lock</code> завершается ошибкой, файлы проекта уже могли быть записаны, но команда конвертации сообщит об ошибке.

## Как найти причину

1. Запустите <code>uv run n8n-transcriper validate workflow.json</code>; для LangGraph добавьте <code>--langgraph</code>.
2. Сопоставьте имя узла и путь параметра с [поддерживаемыми настройками](supported-nodes.md).
3. После конвертации проверьте <code>conversion_report.md</code>, комментарии в generated <code>main.py</code> и TODO в модулях.
4. Если TODO-функция выбрасывает <code>NotImplementedError</code>, сначала реализуйте отмеченный параметр, затем запускайте весь workflow.

Сгенерированные функции логируют начало и завершение узла. Runtime-исключение включает имя узла и исходную причину, после чего по умолчанию завершает workflow. Внешние API, SMTP, PostgreSQL и пользовательская схема Data Table должны быть доступны и настроены самостоятельно.
